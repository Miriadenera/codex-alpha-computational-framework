# Codex Alpha Computational Framework Roadmap

**Closed Beta to Scalable Space-Data Intelligence Platform**  
**Technical and Strategic Roadmap 2026–2029**

The **Codex Alpha Computational Framework** is currently in a **Closed Beta Research Demonstrator** phase.

The current system already provides a working local research environment for Gaia DR3 candidate prioritization, anomaly analysis, graph-based source ranking, astrometric dynamics, candidate investigation and external validation workflows.

This roadmap defines the planned evolution from the current closed-beta demonstrator toward a scalable, AI-assisted and institutionally deployable space-data intelligence platform.

---

---

## Development Philosophy

The framework follows four guiding principles:

1. **Scientific caution**  
   Outputs are candidate-level indicators, not final astrophysical classifications.

2. **Explainable prioritization**  
   Candidate scores must remain interpretable and traceable to input data or proxy calculations.

3. **Human-in-the-loop validation**  
   The framework supports researchers, but does not replace expert review or external catalogue validation.

4. **Scalable architecture**  
   The current local-first prototype must evolve toward larger datasets, automated workflows and cloud-ready deployment.

## Candidate Binary / Comoving Pair Scoring

One important future development direction is a transparent probability-style score for possible binary or comoving pair candidates.

This score should not claim certainty.

It should combine indicators such as:

- angular separation
- parallax consistency
- proper motion vector similarity
- tangential velocity compatibility
- radial velocity compatibility where available
- Gaia NSS presence where available
- photometric compatibility
- neighbourhood density
- probability of chance alignment

The output should be framed as:

```text
binary / comoving pair candidate priority score
```

not as:

```text
confirmed binary probability
```

This distinction is essential for scientific caution.

## AI Integration Strategy

The AI layer should be introduced progressively.

### Phase 1 — Explainable Classical ML

- Isolation Forest
- Random Forest
- Gradient Boosting
- XGBoost / LightGBM style models where appropriate
- interpretable feature attribution
- uncertainty-aware scoring

### Phase 2 — Graph-Based Intelligence

- graph similarity learning
- node embedding experiments
- graph neural network prototypes
- structural anomaly detection
- relational candidate prioritization

### Phase 3 — Scientific Assistant Layer

- local or hosted LLM-assisted dossier drafting
- validation step recommendation
- catalogue context summarization
- natural-language query support
- human-in-the-loop review

The AI layer must remain transparent, auditable and subordinate to scientific validation.

## Risks and Mitigation

### Risk: Scientific overclaiming

Mitigation:

- strict candidate-level language
- explicit scientific caution
- external validation workflow
- no unsupported claims of discovery

### Risk: Dataset scalability

Mitigation:

- modular ingestion architecture
- cloud-ready roadmap
- batch processing and queue systems
- larger dataset testing

### Risk: AI opacity

Mitigation:

- explainable models first
- feature attribution
- uncertainty reporting
- human-in-the-loop validation

### Risk: Technical fragility

Mitigation:

- code freeze before presentations
- build validation
- automated tests
- staged refactoring
- static analysis triage

### Risk: Market uncertainty

Mitigation:

- ESA BIC feedback
- early research user interviews
- open-source visibility
- institutional partnership exploration
- focused use cases
