# Codex Alpha Computational Framework Roadmap

**Closed Beta to Scalable Space-Data Intelligence Platform**  
**Technical and Strategic Roadmap 2026–2029**

The **Codex Alpha Computational Framework** is currently in a **Closed Beta Research Demonstrator** phase.

The current system already provides a working local research environment for Gaia DR3 candidate prioritization, anomaly analysis, graph-based source ranking, astrometric dynamics, candidate investigation, stellar reconstruction, candidate dossier generation and external validation workflows.

This roadmap defines the planned evolution from the current closed-beta demonstrator toward a scalable, AI-assisted and institutionally deployable space-data intelligence platform.

## Development Philosophy

The framework follows four guiding principles:

1. **Scientific caution**  
   Outputs are candidate-level indicators, not final astrophysical classifications.

2. **Explainable prioritization**  
   Candidate scores must remain interpretable and traceable to input data or proxy calculations.

3. **Human-in-the-loop validation**  
   The framework supports researchers, but does not replace expert review or external catalogue validation.

4. **Scalable architecture**  
   The current local-first prototype must evolve toward larger datasets, automated workflows and cloud-ready deployment.

## Strategic Validation Direction

The Codex Alpha Computational Framework is intended to act as a pre-validation intelligence layer before external astronomical validation.

It does not replace established astronomical services such as CDS Portal, SIMBAD, VizieR, Aladin or X-Match.

The long-term objective is to prepare Gaia-derived candidates for structured inspection through external catalogue and validation systems.

The framework aims to support:

- candidate prioritization before external catalogue inspection
- structured handoff from internal dossiers to external validation services
- catalogue-aware validation workflows
- CDS-oriented interoperability planning
- SIMBAD and VizieR object-context inspection
- Aladin-oriented sky visualization workflows
- X-Match-oriented cross-identification workflows
- clear distinction between internal candidate scores and external scientific validation

No official CDS integration, endorsement or partnership is claimed at this roadmap stage.

## Candidate Binary / Comoving Pair Scoring

One important future development direction is a transparent probability-style score for possible binary or comoving pair candidates.

This score should not claim certainty.

It should combine indicators such as:

- angular separation
- parallax consistency
- proper motion vector similarity
- tangential velocity compatibility
- radial velocity compatibility where available
- Gaia NSS presence where available
- photometric compatibility
- neighbourhood density
- probability of chance alignment
- external catalogue context where available
- crossmatch consistency where available

The output should be framed as:

```text
binary / comoving pair candidate priority score
```

not as:

```text
confirmed binary probability
```

This distinction is essential for scientific caution.

## Risks and Mitigation

### Risk: Scientific overclaiming

Mitigation:

- strict candidate-level language
- explicit scientific caution
- external validation workflow
- no unsupported claims of discovery
- clear distinction between prioritization and confirmation

### Risk: Dataset scalability

Mitigation:

- modular ingestion architecture
- cloud-ready roadmap
- batch processing and queue systems
- larger dataset testing

### Risk: AI opacity

Mitigation:

- explainable models first
- feature attribution
- uncertainty reporting
- human-in-the-loop validation

### Risk: Technical fragility

Mitigation:

- code freeze before presentations
- build validation
- automated tests
- staged refactoring
- static analysis triage
- keep-alive strategy for WebGL-heavy dashboard views where needed

### Risk: External service dependency

Mitigation:

- treat CDS Portal, SIMBAD, VizieR, Aladin and X-Match as external validation services
- avoid claiming official integration unless formally established
- provide graceful degradation when external services are unavailable
- preserve local-first execution for core dashboard functions
- keep validation links and handoff workflows transparent and user-controlled

### Risk: Market uncertainty

Mitigation:

- ESA BIC feedback
- early research user interviews
- open-source visibility
- institutional partnership exploration
- focused use cases
- clear positioning as a pre-validation candidate-intelligence layer

The long-term vision is to evolve the Codex Alpha Computational Framework into an explainable, AI-assisted space-data intelligence platform.

The system should help researchers and institutions move from large astronomical catalogues to structured, prioritized and validation-ready candidate investigations.

The framework is not intended to replace scientific expertise.
